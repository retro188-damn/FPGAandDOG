## 1. 手册怎么说

- 运动控制手册：**自主模式 `0x21010C03`**、**手动模式 `0x21010C02`**。
- 同一份手册的速度指令一节写明：**自主模式下机器人响应"由感知主机下发"的速度指令，
  手动模式下响应手柄**。这正是"发 UDP 速度指令"能生效的前提。
- 感知板手册的快速开始写着："使机器狗起立，并**启动 APP 设置页中的自主模式**"。
  → 自主模式原本是**给人用 APP 打开**的，协议指令是等价替代。

## 2. 我们实测到的事实（2026-10-26）

| 时间 | 动作 | 观测 |
|---|---|---|
| 18:43 | 手发 `0x21010C03`（1 帧） | `robot_motion_state` 仍为 0，但随后 5 cm 速度探针**生效** |
| 18:47 | 走完整链路 0.6 m | 6.9 s、0.601 m，抓包确认每帧都带 vx |
| 20:48 | 又走 0.605 m | 正常 |
| 20:57 | 发 `0x21010C03`（1/3/10 帧） | `robot_motion_state` 始终 0；5 cm 探针**不生效**，报"不响应" |
| 21:14 | 发 `0x21010C02`（手动） | 状态帧正常，`basic=6 error=0` |
| 21:17 | 再发 `0x21010C03` | 探针 0.051 m **生效** |

两条关键结论：

1. **`robot_motion_state` 不能作为模式判据**——它在我们所有成功移动的样本里都是 0。
2. 速度指令是否生效**会变化**，且与"谁最近碰过手柄"相关（21:14 之前用户动过手柄，
   之后恢复了）。所以模式/控制权很可能不是单一标志位，而是**多源仲裁**。

## 3. 候选解释（按可能性排序）

| # | 假设 | 支持证据 | 反证 / 待查 |
|---|---|---|---|
| H1 | `robot_motion_state` 只反映"APP/手柄侧"的模式，不反映 UDP 速度通道是否被接受 | 所有成功样本该字段都是 0 | 需看改手柄后该字段是否变化（E1） |
| H2 | 控制权由**最后动作的一方**持有（手柄 > 感知主机 > 我们） | 手柄动作后探针失效、再发 0x21010C03 又恢复 | 恢复需要多久、是否与 0x21010C03 有关（E2） |
| H3 | 0x21010C03 需要**特定前置状态**（站立 `basic=6`、无故障） | 两次成功都是 `basic=6 error=0` | E3 里人为制造 `basic≠6` 对比 |
| H4 | 手柄的"动作类命令"本身会让机身进入某种**局部运动/踏步**状态，把控制权抢走 | 用户描述"只会向后和踏步" | 需要看抢权时的 `basic/gait/vel_body`（E4） |

## 4. 待执行实验（开机后按顺序，全部需本人在场 + 遥控器在手）

**通用准备**：`python tools\remote.py perception "cd /home/ysc/robot_state_relay && bash start_state_tee.sh"`
恢复状态流；另开一窗跑 `python tools\state_monitor.py`（或 `tools\voice_agent.py --no-read --no-tts`
只做状态采集）。所有会动狗的命令**先报告后执行**（`docs/conventions.md` §1）。

### E1 —— 模式字段的语义（5 分钟，狗站立、手柄在旁不动）
1. 记录基线：`basic / gait / robot_motion_state / vel_body`。
2. APP 里手动切自主 → 观察 `robot_motion_state` 是否变化。
3. 发 `0x21010C02` → 再观察。
4. **判定**：若字段随 APP 变化而协议不变 → 支持 H1（字段只跟 APP 走）；若都不变 → 字段无用，弃用。

### E2 —— 控制权仲裁（10 分钟）
1. 确保能移动（先 5 cm 探针成功）。
2. 人动手柄：只推**摇杆**（速度），不按动作键 → 记下探针多久后失效。
3. 再只按**动作键**（如 打招呼） → 记下探针多久后失效。
4. 失效后依次尝试：发 `0x21010C03` 一帧 / 等 5 s / 发 `0x21010C02` 再 `0x21010C03` → 看哪种恢复最快。
5. **判定**：得到"抢权 → 恢复"的最短路径，写进交接流程。

### E3 —— 前置状态（5 分钟）
在 `basic=6/error=0` 与"刚趴下再起立""刚上电未起立"三种状态下各发一次 `0x21010C03` + 5 cm 探针，
**判定**：0x21010C03 是否要求站立态。

### E4 —— "手柄动作导致踏步后退"复现（10 分钟）
1. 记录姿态与位置；2. 让人按一次动作键；3. 录 3 s 状态（`basic/gait/vel_body/pos`）；
4. **判定**：复现 3 次即定性；把 `vel_body` 的符号与幅值记下来（是"后退"还是"踏步时的前后抖"）。
