# 系统架构：语音指令 → 机械狗自主执行 → 语音播报

> 状态：2026-10-25 深夜版。对应提交截止 2026-11-04。
> 本文只描述**结构、职责、技术与待办**，不讲实现细节（细节在各 runbook）。

## 1. 一句话架构

**笔记本当大脑**（听、想、说、记账）、**ZYNQ 的 PL 当刹车闸门**（看得见速度、能超时归零）、
**机械狗当手脚**（收速度、走、回状态）、**感知板当状态中转**（把狗的状态分发给需要的人）。

```
                     ┌──────────────────── 笔记本 PC 192.168.1.89（大脑）────────────────────┐
   麦克风 ──► ASR ──►│ 意图解析 ──► 任务规划 ──► 命令生成 ──► 安全闸门客户端 ──► TTS ──► 喇叭   │
                     │      ▲              │                                   │              │
                     └──────┼──────────────┼───────────────────────────────────┼──────────────┘
                            │              │ AXI4-Lite 写寄存器                 │ UDP 0x0140/41/45
                            │              ▼                                    ▼
                       状态帧 43900   ┌─────────┐                        ┌──────────────┐
                            │        │ ZYNQ PL │ OUT_VX/VY/WZ           │ 运动主板 120 │
                            │        │ 安全闸门 │ ────────► 编码成 UDP ──► │ RK3588 43893 │
                            │        │ 看门狗   │                        └──────┬───────┘
                            │        └─────────┘                               │ 状态帧
                            │               ▲                                  │ 0x0901 100Hz
                            │               │ 43000? 状态帧                     ▼
                            │        ┌──────┴─────────────────────────── 感知板 103 ──────┐
                            └────────│  state_relay.py  (监听 43897 → 转发 89/101)       │
                                     │  ROS Melodic: qnx2ros / ros2qnx / transform       │
                                     └───────────────────────────────────────────────────┘
```

**关键一跳**：速度命令必须经过 PL 的数字通路再发出去。这样"看门狗超时归零"才是硬件行为，
不是软件定时器的承诺——这是本项目在比赛里的技术含量所在，也是报告里要重点写的。

## 2. 四种角色的边界

| 角色 | 设备 | 负责 | 不负责 |
|---|---|---|---|
| **大脑 / 上位机** | 笔记本 192.168.1.89 | 语音识别、意图解析、任务规划、话术、日志、把速度写进 PL、读 PL 输出的速度再编码成 UDP | 不做硬实时保护；不直连狗的运动控制内部 |
| **安全闸门** | ZYNQ PL（101 板） | 命令超时归零（看门狗）、软急停闩锁、命令/超时计数、硬件时间戳、心跳计数 | 不发网络包、不解析协议、不做决策 |
| **运动控制** | 狗运动主板 120（RK3588） | 收 UDP 速度指令、步态与平衡、电机控制、上报机器人状态 | 不知道"任务"是什么 |
| **状态中转** | 狗感知板 103（Xavier NX） | ROS 桥接（qnx2ros/ros2qnx）、把 43897 的状态分发给 PC 与 ZYNQ、将来跑视觉 | 不做决策、不下发速度（除 ROS 导航栈自身） |

## 3. 两条数据通路

### 3.1 下行：一句话怎么变成狗的动作

```
用户说话
  → [PC] 麦克风 16 kHz（2 声道阵列，独占不需要；共享+2ch 即可）
  → [PC] sherpa-onnx paraformer-zh int8（CPU，RTF≈0.015）
  → [PC] 文本
  → [PC] 规则引擎 parse_intent() → {"intent":"goto","target":3,"actions":["read_digits"]}
  → [PC] plan_from_intent() → 步骤序列 [MOVE 3, SPEAK, READ_DIGITS 3, SPEAK]
  → [PC] 命令生成 frames_for_command(vx,vy,wz) → 三个 double 小端帧
  → [PC] 写 AXI4-Lite：CMD_VX/VY/WZ + TIMEOUT_MS + CMD_ARM
  → [PL] 闸门放行：把 CMD_* 打到 OUT_*，并重置看门狗
  → [PC] 读 OUT_VX/VY/WZ → 拼 UDP（code 0x0140/0x0141/0x0145）→ 120:43893
  → [狗] 执行；若 PC 掉线 >TIMEOUT，PL 自己把 OUT_* 归零，PC 恢复后读到 0
```

### 3.2 上行：狗现在是什么状态

```
狗运动主板 120
  → UDP 内部链路，状态帧固定发往 103:43897（jy_exe/conf/network.toml 里写死）
  → [103] state_relay.py 监听 43897
        ├→ 转发 PC 192.168.1.89:43900（state_monitor 解码、落 JSONL）
        ├→ 转发 ZYNQ 192.168.1.101:43900（未来给 PL/PS 用）
        └→ 转发本机 43896（保持 qnx2ros 原逻辑，/leg_odom 等 ROS 话题不断）
```

状态帧事实：`code=0x0901`，载荷 200 字节（`struct.pack("<...")`，4 字节对齐），**100 Hz**；
含 roll/pitch/yaw、世界坐标、机体速度、电量、超声波前/后距、error_state、motion_state。

### 3.3 视觉通路（未实现）

```
摄像头 120:8554（RTSP，H.264，640×480@30）
  → 取帧（gst/ffmpeg/OpenCV 任一）
  → 检测 + 识别数字
  → 文本 → pipeline.digit_sentence() → TTS 播报
```

## 5. FPGA 部分（为什么值得写进报告）

| 项 | 内容 |
|---|---|
| 器件 | XC7Z020CLG400-2，PL 时钟实测 **27.777 MHz**（PS 配置写 41.667，实际不分频出来 27.778——已作为实测事实记入 RTL 常量） |
| 总线 | AXI4-Lite 从设备，基地址 `0x43C00000`，寄存器 4 字节对齐 |
| 核心功能 | ① 看门狗：`CMD_ARM` 每次写入重装 `TIMEOUT_MS`，倒数到 0 → `fault_timeout` 粘性置位、`OUT_*` 归零 ② 软急停闩锁 ③ 命令/超时/重装计数 ④ 27 位心跳计数器（做时间戳） |
| 验证 | 板端 `gate_test.py` 27 项断言全过：时钟比对、斜坡整形、跟随、超时、闩锁、清除、急停、计数递增 |
| 部署 | PYNQ overlay：`system.bit` + `system.hwh`，`Overlay()` 加载 0.55 s，寄存器 `mmio` 直接读写 |
| 待接 | 把 `gate_bridge` 的 `PlGate` 与狗的 UDP 出口串起来（当前 PC↔PYNQ 已验证，PYNQ→狗未验证） |

## 6. 技术选型与理由

| 选择 | 备选 | 为什么选它 | 代价 |
|---|---|---|---|
| ASR: sherpa-onnx paraformer-zh int8 | 云端 ASR、讯飞 SDK | 离线、无账号、CPU 就够（RTF 0.015）、模型已在本机 | 近音字错误（"数字"→"书"）；无热词 |
| 意图：规则引擎 | LLM 微调、BERT 分类 | 零依赖零延迟、可完全回归测试、行为可预测 | 句式覆盖靠手写；复杂指令要扩规则 |
| TTS: Windows SAPI | 讯飞离线 TTS、VITS | 系统自带、离线、CPU 开销极小 | 音色机械；只有 Huihui 一个中文音色 |
| 安全闸门：PL 硬逻辑 | 软件定时器 | 软件挂了/被抢占时仍能归零；可计时可计数；是"用 FPGA"的正当理由 | 多一次 AXI 往返（微秒级） |
| 上位机↔狗：UDP 明文协议 | ROS2、MoveIt | 狗只认这个；无需在狗上装东西 | 无校验无重传，需自己做心跳 |
| 状态旁路：103 中转 | 改 120 配置 | 不动狗的任何配置，可回滚；103 本来就在跑 ROS 桥 | 多一跳延迟（毫秒级） |
| 开发环境：Windows + Git Bash + SSH | WSL/Linux 主机 | 现有笔记本就是演示机，不引入新硬件 | 路径/编码/换行坑多（已踩过一批） |

## 8. 风险登记

| 风险 | 影响 | 现在的对策 |
|---|---|---|
| 狗的速度通道不接受外部客户端 | P0-1 失败，MVP 退回"狗自己跑" | 先测；不行就改用 103 上的 ROS `/cmd_vel` 注入（需 103 权限，已有） |

| 时间只剩 10 天 | 功能做不完 | P0 五件事优先，视觉可以先用"贴纸+模板匹配"的笨办法 |
| 演示现场网络 | 三块板 + PC 全在同一交换机，无外部依赖 | 不依赖外网；ASR/TTS 全离线 |
| 笔记本电池 | 背在狗背上 | 算力放置规则见 conventions §7，短时演示足够 |
