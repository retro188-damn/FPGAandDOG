# 待办 3：视觉是否该换成多模态小模型（VLM）

## 问题
现在的读数字是「规则找卡片 + 连通域分字 + MNIST MLP 分类 0-9」，
在干净场景 97.5%，但真实环境（旋转、透视、反光、杂物、不同手写）会掉到 60% 上下。
多模态小模型（VLM）能把"看图直接回答"作为替代路线。

## 本机现状（2026-10-26 实测）
| 项 | 结果 |
|---|---|
| `torch` / `transformers` / `onnxruntime` / `openvino` / `modelscope` 包 | **均未安装** |
| huggingface.co 直连 | **TimeoutError**（不可达，无法直接下模型） |
| pypi（阿里云镜像） | 可达，装 `sounddevice` 时验证过 |
| modelscope.cn | 可达（86 ms） |
| 笔记本 NPU | 设备在（PCI `1022:17f0`），但**无可用运行时**（需要 Ryzen AI 软件栈） |

结论：**今晚无法做真实 VLM 评测**——缺推理栈、缺模型源、缺现场样本。
不装 `torch`（≈200 MB + 依赖）属于"擅自安装未授权软件"，按规约必须先报批。

## 评测所需（一旦批准）
1. 装 CPU 版推理栈：`pip install torch --index-url ...` + `transformers`（或 `onnxruntime` + 导出模型）。
2. 模型候选（体积 / 预期 CPU 延迟，**均为待实测，不是结论**）：
   - SmolVLM-256M / 500M：~0.5–1 GB，单图 CPU 推理预计 1–3 s；
   - Moondream2：~1.7 GB，预计 3–8 s；
   - Qwen2.5-VL-3B：太大，CPU 不现实。
3. **30 张现场照片**（不同角度、光照、纸张、字迹），当前只有 4 张真机帧。

## 验收对照（写死在脚本里，避免自说自话）
`tools/bench_vlm.py`（待写）：同一批 30 张，比较
- 现管线：`read_digits` 端到端正确率（当前压力集 63.5%，真实照片待测）；
- VLM：正确率 / 单次延迟 / 峰值内存；
达标线：**≥27/30 且单次 < 2 s**，否则不替换。

## 建议（决策项，等用户拍板）
优先做**增广 + 数据**（已验证 36.5% → 63.5%，零成本、可离线），
VLM 作为"若时间富余再试"的备选；不建议在没有 30 张现场样本前下结论。
