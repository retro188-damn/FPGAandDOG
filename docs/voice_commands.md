# 语音交互清单（唯一口径）

> 这份文件是**语音能听懂什么**的唯一依据。代码里任何词表变更都必须同步改这里，
> `tests/test_voice_commands_doc.py` 会在不同步时直接变红。
> 最后更新：2026-10-27（对应 `host/app/voice/agent.py` + `host/app/voice/intent.py`
> + 常驻代理 `tools/voice_agent.py`；当天新增「走近再读」行为，见第 9 节）

## 0. 两层结构

```
麦克风 → 唤醒层(agent.py)：唤醒词 / 停词 / 退出词 → 指令层(intent.py)：goto/read_digits/stand/lie/stop
```

唤醒层管"要不要听"，指令层管"听懂什么"。**没带唤醒词的话，指令层根本不会被调用。**

## 1. 唤醒词（必须在这句开头）

| 说法 | 说明 |
|---|---|
| 小狗 | 标准唤醒词 |
| 小狗小狗 | 连说两遍，噪声环境下更稳 |
| 小狗狗 | ASR 常见变体 |
| 小勾 / 小够 / 肖狗 | 噪声下的同音误识别，容忍 |

规则：
- 唤醒词后面直接跟指令 → 一句话执行（「小狗，去一号位置」）。
- 只说唤醒词 → **待命一次**，等紧接着的下一句（8 s 内），说完自动解除待命。
- 待命期间又说了唤醒词（「小狗」…「小狗小狗」）→ **继续待命**，不会回「没听懂」
  （2026-10-26 实跑：这样丢了整整一条指令，已修）。
- 唤醒词出现在句子中间不算（「我今天看见小狗了」不会触发）。
- 例外：**只读命令（读数字）可以不带唤醒词**，见第 5 节。

## 2. 停词（必须在这句**开头**，不需要唤醒词）

| 说法 | 行为 |
|---|---|
| 停 / 停下 / 停下来 / 停止 | 立即停车（当前这一步中断），播报「停」 |
| 别动 / 不要动 / 站住 | 同上 |
| 急停 | 同上 |

- 只在句首生效：**「哎它停得挺稳」不算**（这是 2026-10-26 实机跑出来的误触发，已修）。
- 带唤醒词也认：「小狗，停下」。
- 停只中断运动，**不退出监听**。

## 3. 退出词（**必须带唤醒词**）

| 说法 | 行为 |
|---|---|
| 小狗，退出 / 小狗退出 | 播报「好的，我退出」，正常退出 |
| 小狗，下班 / 小狗，结束 / 小狗，关闭监听 / 小狗，退出监听 | 同上 |
| 退出 / 结束（没有唤醒词） | **不退出**，闲聊里的"结束"太常见 |

## 4. 指令：去某号（`goto`）＝ 找到写着该数字的卡片并走过去

> **2026-11-01 改语义**：以前是"往前走 0.6 m × 编号"，现在改成
> **"转一圈找到写着 N 的卡片，然后朝它走近到能读清楚"**。场地里不再有等距站点，
> 编号指的就是卡片上的数字。

移动动词（任一即可）：`去` `到` `前往` `过去` `走到` `带我去`
（`到` 有排除规则：看到 / 说到 / 感到 / 得到 / 找到 / 遇到 / 想到 不算移动。）

位置表达（都能听懂）：

| 说法 | 解析 |
|---|---|
| 去八号位置 / 去八号 | target=8 |
| 去第三号位 / 去第3个位置 / 去第三个点 | target=3 |
| 去位置2 / 去标号四 / 去编号5 / 去点六 | target=2/4/5/6 |
| 去三 | target=3（弱匹配，confidence 0.8） |

执行顺序（`tools/voice_agent.py:_fetch_worker`）：

1. **转圈找**：九个停点 `0 / ±40 / ±80 / ±120 / ±160`，每个停点读一次；
2. 读到 target 且置信度 ≥ `--seek-confidence`（默认 **0.80**）→ 认它；
3. **走近**：每次前进 `--approach-step`（0.15 m），直到卡片宽 ≥ `--approach-px`（默认 120 px）；
   每段前都重发一次控制权帧（狗停一次就丢速度流）；
4. **站定再读**：等 1.5 s 停稳后连拍挑帧，播报"板子上写的是X"；
5. 一圈没找到 → 播「没找到数字8，我看到的数字有一、五」，**不移动**。

为什么停在 120 px：真机实测这是"能读出来"的下限（86–111 px 读不出字形），
2026-11-01 试过 150/180 px，走近后反而在一次判断里把 5 当成 8，已改回 120 px。

## 5. 指令：顺便读数字（`actions: ["read_digits"]`）

只要句子里出现下面任一词，就带上 `read_digits`：

`数字` `号码` `标号` `编号` `识别` `读数` `看` `读` `查` `念` `多少`

例：「小狗，去一号位置看看数字」→ `{"intent":"goto","target":1,"actions":["read_digits"]}`。

否定会被识别：`不看` `别读` `不用识别` `不要念` → 不添加 `read_digits`。

> `read_digits` **会真的读**：连拍 4 帧、只保留清晰且卡片完整的帧投票，然后播报五种结果之一：
> 「板子上写的是三」/「我看到有点像三，但不太确定」/
> 「我没看到数字，能再靠近一点吗？」/「有点糊，我再看一眼」/
> 「我的相机没连上，请检查一下网络」。
> 常驻代理还多一步：卡片太小就先走过去（第 9 节）。
>
> 也可以**单独**说「看看是什么数字」「读一下号码」——那是 `intent=read`，狗不移动。
> 这类**只读命令不需要唤醒词**（2026-10-26 实跑：用户连说三遍「看看是什么数字」全被忽略，
> 因为它不带动狗，风险为零，所以放开）。移动类命令仍然必须带唤醒词。
> 防误触：句子里必须同时有动作词（看看/看一下/读/念/识别/扫…）且意图判定为 read，
> 「我在看这个数字」「这个数字挺好看」不会被当成命令。

## 6. 指令：站立 / 趴下

| 说法 | intent |
|---|---|
| 站起来 / 起立 / 起身 / 站立 | `stand` |
| 趴下 / 卧倒 / 趴着 | `lie` |

当前 runner **不执行**这两类（涉及控制权，按规约第 10 条必须逐次人工批准），只会记日志。

## 7. 会明确回「没听懂」的话

- 没有动词也没有位置：「一号位置」（缺动词）、「看一下」（缺位置）。
- 编号超出 0–9（如「去十二号」）。2026-11-01 起 0 和 9 也是合法目标，
  因为编号指的是卡片上的数字，不再是 1–8 号站点。
- 纯闲聊：「今天天气不错」。

以上回复都为「没听懂，再说一遍」，不产生任何运动。

## 8. 更改与同步规则

1. 改 `WAKE_WORDS` / `STOP_WORDS` / `EXIT_WORDS`（`host/app/voice/agent.py`）或
   `intent.py` 的词表 → **同一个提交里**更新本文件。
2. `tests/test_voice_commands_doc.py` 逐项断言：代码里的每个词都出现在本文件里，
   且本文件不残留已删除的词。漏更新 → 测试失败。
3. 每轮交付小结里提一句"语音词表是否变化"。

## 9. 常驻代理的「走近再读」（`tools/voice_agent.py`，2026-10-27 真机跑通）

单独说「看看是什么数字」时，狗先判断**够不够近**，再决定读还是走过去。

### 9.1 判断依据：卡片在画面里的像素宽度

框宽就是距离的替身（同一张卡，越近越宽）。真机实测：

| 框宽 | 结果 |
|---|---|
| 86–111 px | 能检测到，但字形太小，读 `""`（empty） |
| **120 px 以上** | 稳定读出，置信度 0.95–0.99 |
| 320 px 以上 | 字形出画，不再前进 |

所以停在 **120 px**（`--approach-px`），硬上限 **320 px**（`--approach-max-px`）。
（2026-11-01 曾在 150/180 px 试过，反而更差，已改回 120 px。）

### 9.2 走多少、怎么走

- 每步 **0.15 m**（`--approach-step`），最多 **6 步**（`--approach-steps`）。
- 每步之前重发一帧自主模式码 `0x21010C03`：**狗每次停下之后会丢掉我们的速度流**，
  不重发就表现为 `dog is not responding`（2026-10-27 复现 4 次）。
- 某一步 `travelled_m < 0.02`（完全没动）→ 自动补发模式码并重试一次。
- 够大就停，**停稳 1.5 s**（`--settle`）后再读，读不准隔 1 s 重拍一次（`--retries`）。

### 9.3 它会说的三句话（除数字播报之外）

| 触发 | 播报 |
|---|---|
| 卡片太小或看不见、开始走近 | **好，我走近点看看** |
| 连走 3 步仍然看不到卡片 | **没看到数字，是不是放偏了？** |
| 运动被拒绝（没开许可 / 姿态不对 / 电量低） | **暂时不能移动，先不靠近了** |

### 9.4 相关开关

| 开关 | 默认 | 作用 |
|---|---|---|
| `--allow-motion` | 关 | 不开就只读不走，也不会发 `0x21010C03` |
| `--approach-px` | 120 | 卡片宽到这个像素就停 |
| `--approach-max-px` | 320 | 超过就硬停，别顶到卡片上 |
| `--approach-step` | 0.15 | 每步走多远（米） |
| `--approach-steps` | 6 | 最多走几步 |
| `--dog-host` | 192.168.1.120 | 狗的运动网关地址（发模式码用） |


## 11. 指令：转圈找数字（`seek`，2026-11-01 新增）

之前只有「走近再读」，狗不会主动**转圈搜索**。现在多了一条独立指令：

| 说法 | intent | target |
|---|---|---|
| 小狗，找数字八 | `seek` | 8 |
| 转一圈找数字三 | `seek` | 3 |
| 小狗去找数字吧（ASR 把"八"听成"吧"） | `seek` | 8（句子修复） |
| 找数字8 / 找号码五 | `seek` | 8 / 5 |

判据先判 `seek`、再判 `goto`：`找数字八` 里的"八"是**要找的卡片**，
不是"8 号位置"，否则狗会直接走过去。

### 11.1 它怎么找

1. 以当前朝向为 0°，依次转到 `0 / +40 / -40 / +80 / -80 / +120 / -120 / +160 / -160` 九个停点；
2. 每个停点**只转不走**，抓一帧看有没有卡片，有就当场读一次；
3. 读到目标数字且置信度 ≥ `--seek-confidence`（默认 **0.80**）→ 停，播报；
   读到了但置信度不够时，会在同一停点再看一眼，两次一致也采信；
4. 读到其它数字 → 记下来继续转；
5. 读到目标数字但置信度不够 → 先对准再重读最多 2 次，仍不够就继续；
6. 转完一圈没有 → 播报"没找到"，并说出这一圈看到过的数字。

**为什么不走近**：2026-10-28 试过"读不出就朝卡片走 0.40 m"，结果停在离障碍物
0.28 m 处，靠遥控器急停才没撞上。搜索只许转身体，走路由 `read`（走近再读）负责。

### 11.2 它会说的话

| 情况 | 逐字 |
|---|---|
| 收到指令 | `好，我转一圈找数字{}` |
| 找到 | `找到了，数字{}在这边` |
| 一圈没找到 | `没找到数字{}，我看到的数字有{}` |
| 没开运动许可 | `要转圈找数字，得先开运动许可` |
| 搜索中出错 | `找数字的时候出了点问题：%s` |

### 11.3 相关开关

| 开关 | 默认 | 作用 |
|---|---|---|
| `--seek-confidence` | `0.80` | 多高的置信度才算"找到了"（2026-11-01 由 0.85 下调：真实 8 只给到 0.821） |

### 11.4 尚未验证

这套逻辑与 `tools/seek_card.py --want` 共用 `host/app/vision/seek.py:hunt_for_digit`，
后者 2026-10-28 真机跑通过（第 3 个停点 `8 @0.85`，重读 `8 @0.778`）；
但**接进常驻语音代理后还没有真机复验**，2026-11-01 下午补测。

- **找到之后至少向前走一步**（2026-11-01 用户指定）：卡片宽度 <150 px 走 0.15 m，
  150–240 px 走 0.10 m，≥240 px 走 0.08 m；只有卡片已经撑满画面（>320 px）才原地读。
  这一步是为了让画面里看得见"走过去"，同时避免一步把它推到 200 px 以上的模糊区。

- **转不动时要说出来**（2026-11-01 15:49 的坑）：`turn_to_heading` 在"狗没响应
  （手动模式/控制权不在我们手里）"时是**返回 `ok=False` 而不是抛异常**。
  早先的代码忽略返回值，于是整圈 9 个停点其实停在同一个朝向，把同一张卡读了 8 次，
  最后播"没找到数字八"。现在每个停点都会检查返回值并重试一次；一圈里有 3 个以上
  停点根本没转过去，就播 **"我转不动了，帮我看看手柄是不是还抓着、或者状态流断了"**，
  不再假装"转过了但没找到"。
