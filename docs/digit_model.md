# 手写数字模型（MNIST + 合成手写字体 + 级联）

分类器是一个纯 numpy 的两层网络（784 → 128/256 ReLU → 10 softmax，Adam 训练）。
不用框架、不联网推理、CPU 单次 ~24 ms/帧（含检测与级联），是"离线可解释"路线的底座。

**当前线上组合（2026-10-29 起）是一个级联**：

- 主模型 `host/model/digits_mlp.npz`（MNIST + 仿射/光度增广，784→128）：印的、转过的数字最准；
- 备模型 `host/model/digits_mlp_v2.npz`（MNIST + 5 万张合成手写字体，784→256）：见过"细笔、竖直压扁、多字体"；
- `load_classifier()` 发现同目录有 `digits_mlp_v2.npz` 就返回 `CascadeClassifier`：
  主模型置信度 ≥ 0.85 直接采信；否则问备模型，**只有**备模型自身 ≥ 0.70 且比主模型高 0.25 以上才改判。

理由见下面第四节：两个模型取平均会在扰动基准上掉 7 例，改成"只在主模型没把握时才问"后，
真机帧 3/8 → 7/8，而扰动基准只掉 1 例。

## 三代模型的实测对比（同一套基准）

| 模型 | 增广 | MNIST test | 场景基准 200 张 | 扰动基准 52 例 |
|---|---|---|---|---|
| `digits_mlp_clean.npz` | 仅平移 | 98.05% | 195 对 (97.5%) | 19 对 (36.5%) |
| `digits_mlp_affine.npz` | 旋转 18° + 缩放/剪切/粗细 | 97.55% | 194 对 (97.0%) | 27 对 (51.9%) |
| **`digits_mlp.npz`（当前）** | 旋转 22° + 缩放/剪切/粗细 + gamma/模糊，2 份副本 | 97.56% | **195 对 (97.5%)** | **33 对 (63.5%)** |

结论：**推理端做多角度投票是错的**（实测让干净的 "2" 变成 "8"，52 例里少了 3 例）；
正确做法是把旋转/粗细/曝光放进**训练增广**，让模型本身不敏感。
代价是 MNIST 纸面精度几乎不掉（98.05 → 97.56），现场扰动精度翻倍。

## 复现

```bash
python tools/train_digits.py --epochs 12 --aug affine --aug-thick --aug-photo     --aug-rotate 22 --aug-copies 2 --out host/model/digits_mlp.npz
python tools/bench_scenes.py --count 200            # 干净场景（合成到真实地板帧）
python tools/bench_stress.py --reader plain         # 4 张真机帧 x 13 种扰动
python tools/bench_ink.py --per-colour 40           # 五种笔
```

`bench_stress.py` 的 13 种扰动：clean、旋转 ±8/±15°、亮度 0.60/0.75/1.30、
对比度 0.6、高斯模糊 1.2/2.0、透视 ±14 px。

## 仍然打不好的场景（明确的边界）

- 旋转 ±15° 且字迹细：笔画方向信息丢失，2/7、5/6 混淆仍存在
- 强逆光或局部过曝（亮度 1.30）：字与纸一起被冲掉
- 卡片只进画面一部分：先被判定"没看到数字"（这是有意的，宁可说没看到也不猜）

这三类是报告里要写明的能力边界，也是"要不要上 VLM"的对照基线。


## 四、2026-10-29：合成手写字体 + 级联（离线，未上真机）

### 为什么换

真机手写卡片的失败**不是分类器"认不出"，而是它没见过这种形状**：

- 卡片躺在地上、相机高 0.31 m → 视线是约 12° 的掠射角，正方形数字到画面里**竖直压扁成 2:1**
  （实测：1.15 m 处一个手写 "8" 是 67×31 px，长宽比 0.46）；
- 马克笔在这个距离上笔画只有 2–4 px，MNIST 的笔画粗得多；
- 同一张 "8" 在 110–140 px 时被读成 `0/5/7`（置信度 0.27–0.56），到 210 px 才读对。

### 做了什么

| 改动 | 说明 |
|---|---|
| `tools/render_digits.py`（新） | 用 200 个系统字体渲染 0–9，再做**竖直压扁 0.45–0.95**、旋转 ±32°、剪切 ±0.30、腐蚀/膨胀、模糊 0–0.8，最后走**与线上完全相同**的 `normalise()` 出 28×28；5 万张耗时约 3 分钟 |
| `tools/train_digits_v2.py`（新） | MNIST 6 万 + 合成 3.6 万，784→256，两遍训练（第二遍补 MNIST 仿射增广，含新增的**竖直压扁**增广） |
| `digit_reader.CascadeClassifier`（新） | 主模型有把握就用主模型，没把握才问备模型；阈值 0.85 / 0.25 / 0.70 |

### 三个数字，按重要性排序

| 指标 | v1（改前） | v2 单用 | 平均集成 | **级联（现用）** |
|---|---|---|---|---|
| 真机 8 张标注帧 | 3/8 | 6/8 | 6/8 | **7/8** |
| 场景基准 200 张（端到端） | 195 (97.5%) | 194 (97.0%) | 195 (97.5%) | **195 (97.5%)** |
| 扰动基准 52 例 | **45 (86.5%)** | 36 (69.2%) | 38 (73.1%) | 44 (84.6%) |
| 五种笔 | 96.2% | 95.0% | 96.2% | **96.2%** |

剩下那 1 个错例是"1.5 m 处的浅铅笔 3 读成 2"——本来就低于可读下限，属已知边界。

### 复现

```bash
python tools/render_digits.py --per-digit 5000 --fonts 200 --out .cache/synth_digits.npz
python tools/train_digits_v2.py --synth .cache/synth_digits.npz --epochs 10 --hidden 256 \
       --out host/model/digits_mlp_v2.npz
python _scratch/eval_real.py          # 8 张真机帧逐张对比
```
