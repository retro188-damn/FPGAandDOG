## 1. 【硬规则】动的东西先报告，后执行

> 2026-10-25 新增，起因：测试 `0x21010202` 时连发 3 帧导致狗自行站起，用户未能提前接管。

凡满足任一条件的操作，**必须先输出《动作预案》并得到用户明确同意**，然后才执行：

1. 会让机器狗产生运动（任何速度指令、起立/趴下、转体、步态、跳跃、打招呼等）；
2. 会改变狗/板子的运行状态（停/启服务、改配置、重启、烧写、断电）；
3. 会改变 FPGA 板上的既有工程/比特流。

《动作预案》必须包含五项：

- **动作**：要发什么、发几帧、持续多久、走多远/多大角度；
- **风险**：最坏情况是什么（走偏、撞、从台上跌落、服务中断）；
- **回退**：出问题怎么一键停止/恢复（发什么帧、执行什么命令）；
- **观察**：我用什么指标判断成功/失败（必须是**可靠**反馈，不能猜）；
- **时间窗**：预计几秒，用户何时需要盯住机器人。

执行纪律：

- 一条指令**只发 1 帧**；需要重复的动作（速度类）必须显式设计为"持续 N 秒后归零"；
- 用户说"停"时立即停止发送并回到零速/手动模式；
- 事后 5 分钟内补记日志。

## 2. 方案先行

每次动手前先输出《变更方案》：目标、现状假设、涉及文件/模块、技术路线、风险与回滚、验证方法。用户回"同意"后再执行。小改动（改注释、补日志、只读勘察）不受此限。

## 3. 日志

- 每模块独立目录，日志放 `logs/`，命名 `模块_YYYYMMDD.log`。
- 格式：`[ISO时间] [级别] [模块] 关键参数/动作`；出错必须附**原始报错全文**、触发输入、执行命令、环境。
- 禁止只说"失败了"。
- 各板时钟不一致（已知：103 显示 2018-01-29，120 显示 2025-12-03），**跨板日志一律以开发电脑时间为准**，并在日志里记录板端 `date` 输出。

## 4. 代码规范

- 注释全英文；Verilog 全英文注释。
- Python 使用类型标注；需在板端（Python 3.6.9）运行的脚本不得使用 3.7+ 语法
  （无 `from __future__ import annotations`、无 `bytes.hex(sep)`、无内置泛型下标）。
- 引脚分配单独成表（`docs/pinmap.md`）。
- 小步提交：每完成一个可验证单元记录变更说明，保持可回退。

## 5. 每轮交付小结

每轮结束输出：做了什么、验证结果（含原始证据）、下一步、遗留问题。

## 6. 报告必须写清职责归属（用户要求）

写报告/提交文档时，必须有一张「流程归属表」，逐环节写明：
- 上位机（PC / 感知板 103 / ZYNQ PS）负责什么；
- FPGA（PL）负责什么；
- 边界在哪里（哪一跳是 PL 介入的、哪一跳是纯软件）。

不允许出现"系统完成 X"这种不区分实现载体的表述。当前分工已确定的骨架：
- 语音识别、意图解析、任务裁决、狗的命令生成与下发：上位机软件。
- 速度命令的**超时归零**（看门狗）、急停闩锁、命令/超时计数、硬件时间戳：PL。
- PL 的输入是上位机写进 AXI4-Lite 的 CMD_*，输出是 OUT_*（再由上位机编码成 UDP 下发）。
  PL 不发网络包、不直接连狗；这一跳的物理实现方式待定（当前走 PS Linux 读 AXIS/寄存器）。

## 7. 算力放置规则（用户要求，2026-10-25）

演示时笔记本大概率**不插电、背在狗背上**，所以每个模型都要有放置理由，不许"能跑就往上堆"。

### 7.1 优先级（从低功耗/低负载到高功耗）
1. **CPU**（默认）。单条指令级推理（ASR/TTS/小分类器）实测成本极低，先用它。
2. **狗身上的算力**（120 RK3588 6 TOPS NPU / 103 Xavier NX 21 TOPS）。
   用的是狗自己的电池，不占笔记本功耗预算，且感知栈已在 103 上跑，天然就近。
3. **笔记本 NPU**（AMD XDNA2，Ryzen AI 7 H 350，约 50 TOPS INT8）。适合常驻/连续推理，
   但需要装 AMD Ryzen AI 软件栈（ORT Vitis EP），当前未装。
4. **笔记本 dGPU**（RTX 5060 Laptop）。只在离线/批处理用（训练、数据集跑分、批量评测），
   **不进演示实时链路**。除非实测证明 NPU/CPU 达不到指标，且已报批。

### 7.2 实测依据（2026-10-25，本机）
- ASR（sherpa-onnx paraformer-zh int8，CPU 4 线程）：8 s 音频 → 墙钟 0.116 s，
  CPU 时间 0.469 s，RTF 0.0145（约 69× 实时）。
- 折算功耗：一条指令约 0.5 CPU 秒 ≈ 0.003 Wh；100 条指令 ≈ 0.3 Wh（电池约 70 Wh）。
- 结论：**ASR/TTS 与意图解析留在 CPU，不需要 NPU，也不需要 GPU。**

### 7.3 流程
- 每个新模型/推理模块上手前，先报一组实测：延迟、CPU 占用、内存、估算功耗，再决定放哪里。
- 报告里必须写明该模块跑在哪台设备、占多少算力（延续第 6 节归属表）。

## 9. 运动操作附加限制（用户 2026-10-26 指令，代码已强制）

| 规则 | 实现 |
|---|---|
| 自主控制时**不许后退**（当前场地） | `MotionExecutor(allow_reverse=False)` 默认；`move(..., reverse=True)` 直接 `MotionRefused` |
| 单次**前进不超过 1.0 m** | `max_distance_m=1.0`（站点间距 0.6 m，留余量） |
| 手柄一动即回手动模式 | 动前确认手柄未被触碰；速度被忽略时执行器 0.9 s 内停车并上报 |

原文（用户）："你自主操控机器狗的时候尽量不要在当下状态下后退，也不要前进超过1m"。

## 10. 控制权变更必须逐次批准（2026-10-26 事故后新增）

**事故**：19:03:32 我在用户说"可以"之后直接发了 `0x21010C03`（自主模式），用户并未对"切换控制模式"这个动作点头；
随后用户碰手柄，遥控器失去对狗的正常控制（前进/后退都变成后退与原地踏步）。

**规则**：
1. `0x21010C02` 手动模式、`0x21010C03` 自主模式、`0x21010202` 起立/趴下、`0x21020C0E` 软急停
   属于"控制权变更"，必须**先报告动作 + 预期现象 + 恢复手段**，等用户明确说"可以/发送"后才执行；
   "可以"只能批准被明确描述的那一个动作，不能推及其他。
2. 代码强制：`tools/dog_simple.py` 对上述四类码要求额外 `--approve-mode`，否则拒绝（exit 3）。
3. 变更后立即读状态回显（basic/mot/err/电量）并回报，再让用户动遥控器确认控制权已经回到手里。

**恢复顺序**（需用户批准）：`0x21010C02` → 遥控器验证 → `0x21010202` 起立/趴下切换 → 软急停后重新起立 → 重启狗的运动服务。

## 12. "自监督学习"在本项目里的定义（用户 2026-10-29 命名）

用户把下面这套**由模型自己看图、自己下结论、再据此修正狗的位置**的闭环，命名为
"自监督学习"。以后用户说到这四个字，不是指机器学习里的那个概念，而是指**这套流程**，
直接按本节执行，不需要再问"你指的是什么"。

### 12.1 一次"自监督学习"的完整动作

1. **停下来**：狗走完 / 转完之后停稳，不许边动边看；
2. **拍两张**：`_scratch/look2.py` 那种两帧连拍，存图并记下 `pos / yaw / pitch / 电量`；
3. **我自己看**：用视觉能力直接看这两张帧，回答三个问题——
   **数字在哪（左/中/右、离中心多少 px）**、**卡片有多大（够不够 110 px）**、
   **有没有漂移或被画面边缘切掉**；
4. **先给结论，不动**：把"现在算什么状态、下一步该往哪个方向修正、修正多少"写清楚；
5. **按结论修正**：前进 / 后退 / 转 ±N°，每一步都重新回到第 2 步；
6. **居中且够大才读**：数字落在画面中心 ±40 px、卡片宽度 ≥110 px，才允许调用 `read_burst`；
7. **留档**：修正前/后的帧、结论、动作写进当天的 `docs/progress.md`。

### 12.2 硬规矩

- **结论先于动作**：没有任何一次"边转边猜"。没出结论就不许发运动指令。
- **不靠固定阈值代替判断**：阈值（110 px / ±40 px / 0.05 m/s）只用于**初筛和复验**，
  最终判断由我看图给出；两者冲突时以图为准，并把阈值的偏差记下来。
- **每次都要留帧**：没有帧就没有结论，事后无法复盘。
- **不许用"看起来对"糊过去**：看不清就写"看不清"并说明缺什么（离太远 / 被切 / 太糊），
  这正是这条流程要消灭的东西。

### 12.3 它和"识别算法"的分工

- 自监督学习负责**把画面摆对**（在不在、偏没偏、够不够大）；
- `digit_reader` / 级联分类器负责**认字**。
- 今晚的教训：8 在 110–140 px 时读成 0/5/7，不是分类器不行，是**画面没摆对**（太远、太扁）。
  所以先跑自监督学习把画面摆正，再谈识别率。
