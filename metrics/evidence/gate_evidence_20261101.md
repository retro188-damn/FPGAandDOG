# FPGA 安全闸门：2026-11-01 真机运行证据

本文档只记录**能从板子自己吐出来的东西**里核实的事实，用来替代"拍一段拔线视频"。

## 1. 时钟说明（重要）

ZYNQ 板子没有 RTC，跑起来时钟是 2021-11-18（固件默认值），而且比 PC 快 **1 小时 34 分 34 秒**。

采集本次证据时实测：

| 时钟 | 读数 |
|---|---|
| 板端 `date` | 2021-11-18 17:34:17 |
| PC `date` | 2026-11-01 15:59:43 |

**换算关系：PC 时间 = 板端时间 − 1h34m34s（日期另算）。**

采集完证据后已用 `sudo date -s` 把板端时钟与 PC 对齐（2026-11-01 15:59:49），
之后再产生的日志时间戳是正确日期。**旧的日志行仍是 2021 时间戳**，看的时候按上表换算。

## 2. 素材来源

| 文件 | 内容 |
|---|---|
| `metrics/evidence/pl_service_run_20261101.log` | 板端 `pl_service.log` 中 **17:15–17:30**（板端时钟）那一段，即 PC 侧 **15:40–15:55** 的几轮语音演示 |
| 本文第 3 节 | 同一时刻 FPGA 内部计数器的只读回读（`tools/pl_cmd.py --watch`） |

## 3. 寄存器回读（此刻）

```
gate=closed armed=n out=(0.00,0.00,0.00) cmd=[0, 0, 0] p50=20.0ms p99=20.8ms over=1016 trips=1
```

| 字段 | 值 | 含义 |
|---|---|---|
| `p50` / `p99` | 20.0 ms / 20.8 ms | 控制周期 50 Hz，抖动 p99 仅 0.8 ms |
| `over` | 1016 | 累计超时/超限事件计数（自本次上电以来） |
| `trips` | **1** | 硬件故障闩锁**至少触发过一次**（粘性，需显式清除） |
| `gate` | closed | 当前闸门关闭、输出为零 |

`trips=1` 说明看门狗真的切断过一次，不是"只写在 RTL 里没触发过"。

## 4. 那段运行里闸门做了什么

板端日志（换算后 = PC 15:40–15:55）共 **84 行**事件：

| 事件 | 次数 | 说明 |
|---|---|---|
| `gate enabled by fresh command` | **42** | 收到新的、非零的速度帧 → 闸门打开、放行 |
| `gate closed: stop command` | **42** | 收到停止帧 → 闸门关闭、输出归零 |
| `gate closed: deadman: no command for 300 ms` | 0 | 这段没触发（说明上位机一直在发帧） |

**42 开 / 42 关，一一配对**：每一段运动都是"新的速度帧开门 → 停止帧关门"，
不存在"绕过闸门直接发给狗"的路径——这正是报告里那条论点的实测依据：

> 速度命令**必须**先经过 PL：没有新的命令帧，闸门在 200 ms 内自己归零；
> 上位机就算整个崩掉，狗也停得住。

## 5. 补测：真的制造了一次"上位机失联"

上面那 42 开 / 42 关是正常演示。为了拿到"上位机死掉、闸门自己关、硬件闩锁"的硬证据，
2026-11-01 16:04 做了一次**受控的失联测试**（脚本 `_scratch/deadman_test.py`）：

1. 向 pl_service 发 15 帧 `vx = 30 mm/s`（0.3 s），**然后故意不发停止帧**——这就是"上位机崩了"的样子；
2. 等待 1.2 s；
3. 回读 FPGA 寄存器。

结果（`metrics/evidence/deadman_20261101.log`，板端时钟已对齐）：

```
[2026-11-01 16:04:45,004] [INFO] gate enabled by fresh command
[2026-11-01 16:04:45,583] [WARNING] gate closed: deadman: no command for 300 ms
[2026-11-01 16:04:50,744] [INFO] gate enabled by fresh command
[2026-11-01 16:04:51,343] [WARNING] gate closed: deadman: no command for 300 ms
```

| 时刻 | `trips` | `over` |
|---|---|---|
| 测试前 | 1 | 1016 |
| 第 1 次失联后 | **2** | 1016 |
| 第 2 次失联后 | **3** | 1016 |

两次失联、两次 +1，`trips` 只增不减（粘性闩锁）。测试结束后 `gate_open=False`、`out=[0,0,0]`，
下一次正常命令到来时 pl_service 会写 `CTRL_ENABLE|CTRL_CLEAR_FAULTS` 自动清故障，不需要人工复位。

**这条证据的含义**：上位机连停止帧都发不出来的那种崩溃（进程被杀、网线拔掉、死机），
200 ms 内闸门自己关、输出归零、硬件计数 +1。狗在测试中没有收到任何有效速度（测试时狗
不在可运动状态，`trips` 的变化完全由闸门侧产生）。

## 6. 已知缺口（不吹）

- 这一段里 **deadman 没触发**（因为演示中上位机一直在发帧），所以"上位机死掉→狗停"这条
  目前只有 `gate_test.py` 的 200.6 ms 超时自检和 `trips=1` 的间接证据，
  **没有一段"掐掉上位机、狗当场停下"的实拍**。
- 如果要补，最省事的做法是在 `gate_test.py` 之外单独跑一次：
  狗走起来 → `taskkill` 掉语音代理 → 观察 `pl_cmd --watch` 的 `trips` 从 1 变 2。
- 板端时钟此前是错的，**视频里如果出现板子日志画面，时间戳会显示 2021 年**，建议避免拍屏幕上的板端日志。
